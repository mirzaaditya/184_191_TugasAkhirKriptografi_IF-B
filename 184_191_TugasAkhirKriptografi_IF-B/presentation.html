Latar Belakang & Permasalahan Keamanan

⚠️ Kelemahan Sistem Konvensional

  • Single Layer Dependency: Hanya bergantung pada pengamanan jalur transmisi (TLS). Jika gerbang login ditembus, data terbuka sepenuhnya.
  • Kebocoran Data-at-Rest: Berkas basis data lokal sering kali disimpan dalam bentuk teks biasa (plaintext), mudah dicuri via serangan offline.
  • Ketiadaan Jejak Forensik (Non-Repudiation): Sulit membuktikan keaslian dan integritas histori transaksi pesan jika terjadi perselisihan data.

🛡️ Solusi yang Diusulkan

  • Pertahanan Berlapis (Defense-in-Depth): Data dilindungi dari level gerbang fisik, biometrik, cipher teks, enkripsi berkas, steganografi, hingga blockchain.
  • Pemisahan Algoritma & Kunci: Pesan teks, berkas lampiran, dan media stego masing-masing menggunakan algoritma dan derivasi kunci yang independen.
  • Audit Trail Nir-Bantah: Setiap transaksi pesan dan berkas diikat ke blok rantai dengan konsensus Proof-of-Work.

Arsitektur Sistem (Defense-in-Depth)

Arsitektur dirancang dalam 3 Lapisan Utama yang saling terintegrasi dalam antarmuka Streamlit:

1. Gerbang Akses 3FA

Otentikasi 3-Faktor memverifikasi:

  • Fisik: USB Dongle (HMAC-SHA256)
  • Biometrik: Wajah (OpenCV)
  • Pengetahuan: Password (PBKDF2)

2. Mesin Enkripsi & Stego

Pengamanan muatan data:

  • Teks: Super Enkripsi (Vigenère + AES-GCM)
  • Berkas: ChaCha20-Poly1305
  • Media: Pre-AES + LSB (PNG, WAV, Video)

3. Integritas & Ledger

Penyimpanan aman dan audit:

  • Basis Data: SQLite Data-at-Rest
  • Audit Trail: Blockchain SHA-256
  • Konsensus: Proof-of-Work (PoW)

Lapisan 1: Otentikasi Tiga Faktor (3FA)

🔑 Faktor 1: Dongle USB

Something You Have:

  • Pendeteksian USB flashdisk fisik otomatis via psutil.
  • Berkas secure_dongle.key memuat token acak yang dienkripsi AES-256-GCM.
  • Ditandatangani secara digital dengan HMAC-SHA256 untuk menjamin anti-modifikasi.

👤 Faktor 2: Biometrik Wajah

Something You Are:

  • Deteksi wajah kamera langsung via Haar Cascade OpenCV.
  • Normalisasi dimensi (200x200 px) & ekualisasi histogram kontras.
  • Pencocokan kemiripan gabungan (Cross-Correlation & Histogram) dengan ambang batas minimal 65%.

🔒 Faktor 3: Sandi PBKDF2

Something You Know:

  • Standar NIST SP 800-132.
  • 100.000 Iterasi derivasi kunci dengan pseudorandom HMAC-SHA256.
  • Cryptographic Salt acak 128-bit (mencegah serangan Rainbow Table).
  • Verifikasi waktu-konstan (constant-time).
Anggota 2

Lapisan 2: Super Enkripsi Pesan Teks

Menggabungkan cipher klasik dan modern secara bertingkat (Cascaded Hybrid Cipher):

Plaintext → [Vigenère Modulo 256] → Intermediate Ciphertext → [AES-256-GCM AEAD] → Final Base64

Vigenère Cipher (Klasik)

  • Implementasi manual murni tanpa pustaka pihak ketiga.
  • Mode Extended Byte (Modulo 256) beroperasi pada UTF-8, menjaga format spasi, tanda baca, dan emoji.
  • Mengaburkan pola frekuensi linguistik teks alami (Confusion).

AES-256-GCM (Modern AEAD)

  • Kunci 256-bit standar militer (NIST FIPS 197).
  • Galois/Counter Mode menghasilkan 128-bit Authentication Tag.
  • Menjamin kerahasiaan sekaligus integritas: modifikasi 1 bit saja langsung membatalkan dekripsi (InvalidTag).

Lapisan 3: Enkripsi Berkas (ChaCha20-Poly1305)

Pemisahan Domain: Berkas dokumen/biner menggunakan algoritma dan kunci yang sepenuhnya berbeda dari pesan teks.

Karakteristik ChaCha20-Poly1305

  • Stream Cipher Modern (RFC 8439): Dirancang oleh Daniel J. Bernstein, beroperasi sangat cepat pada data biner besar.
  • Operasi ARX (Add-Rotate-XOR): Tidak menggunakan tabel memori S-Box, secara alami kebal terhadap cache-timing attack pada CPU tanpa instruksi hardware AES-NI.
  • Poly1305 MAC 128-bit: Mengunci keaslian berkas secara byte-demi-byte.

Format Kontainer Berkas

  • [MAGIC: SMSG_ENCF] (9 Byte Header)
  • [VERSION: 1] (1 Byte Versi)
  • [NONCE: 12 Byte] (96-bit Nonce Acak)
  • [METADATA TERENKRIPSI] (Nama berkas asli & ukuran terproteksi)
  • [PAYLOAD + POLY1305 TAG]
  • Throughput Nyata: Mencapai 835,6 MB/s.

Lapisan 4: Keamanan Basis Data SQLite (Data-at-Rest)

Mencegah kebocoran data jika berkas app_database.db dicuri atau dibuka paksa dari luar aplikasi.

Field-Level AES-256-GCM

  • Transparan pada DAO: Konten pesan dienkripsi otomatis sebelum perintah INSERT, dan didekripsi otomatis saat SELECT.
  • Pemisahan Kolom Fisik: Kolom encrypted_content, content_nonce (12B), dan content_tag (16B) tersimpan terpisah.
  • Non-Repudiation Hash: Kolom message_hash menyimpan SHA-256 pesan untuk dihubungkan ke Blockchain.

Bukti Fisik Disk (Zero Leakage)

  • Pemeriksaan biner mentah membuktikan teks asli 100% TIDAK DITEMUKAN di disk.
  • Deteksi Manipulasi: Jika penyerang mengedit ciphertext via SQLite Browser, fungsi verify_all_records_integrity() langsung mendeteksi baris yang rusak.

Lapisan 5: Steganografi Multimedia LSB

Prinsip Baku: Pesan rahasia wajib dienkripsi AES-256-GCM terlebih dahulu sebelum disisipkan ke bit LSB (Least Significant Bit).

🖼️ Gambar PNG

  • Format PNG lossless (Deflate compression).
  • Penyisipan bit LSB pada saluran warna piksel RGB.
  • Operasi tervektorisasi NumPy sangat cepat (21,8 ms).

🎵 Audio WAV

  • Format WAV 16-bit PCM uncompressed.
  • Modifikasi LSB sampel amplitudo suara.
  • Perubahan hanya $\pm 0,003\%$, sepenuhnya tidak terdengar oleh manusia.

🎬 Video Lossless FFV1

  • Pecah frame video dengan OpenCV.
  • Sisipkan bit LSB ke frame piksel secara berurutan.
  • Satukan kembali dengan Codec FFV1 (100% bit-exact lossless).

Lapisan 6: Audit Trail Blockchain SHA-256

Struktur Entitas Blok

  • Index: Nomor urut (0 = Genesis Block).
  • Timestamp: Waktu pencatatan UTC.
  • Data: Hash transaksi pesan, berkas, atau log login.
  • Prev_Hash: Hash blok sebelumnya (pengikat rantai).
  • Nonce: Pencacah Proof-of-Work.
  • Hash: SHA-256 kanonikal blok.

Konsensus & Validasi

  • Proof-of-Work (PoW): Memaksa penambangan mencari hash berawalan "00...". Mencegah penulisan ulang riwayat transaksi masa lalu.
  • validate_chain(): Memvalidasi keutuhan 3 aspek:
    1. Kesesuaian hash internal blok.
    2. Pemenuhan target PoW.
    3. Kekokohan sambungan prev_hash.

Analisis Kritis: Kelemahan & Keterbatasan

Steganografi LSB

Kelemahan:

  • Tidak tahan kompresi lossy media sosial (misal JPEG WhatsApp).
  • Rentan terhadap manipulasi geometri (resizing/cropping).
  • Mitigasi: Berkas wajib ditransmisikan dalam mode dokumen asli.

Password Hashing (PBKDF2)

Kelemahan:

  • Tidak memory-hard dibandingkan Argon2id, sehingga teoretis rentan ASIC/FPGA.
  • Mitigasi: Penggunaan 100.000 iterasi dan salt unik 128-bit menjamin perlindungan standar NIST.

Hardware Dongle

Kelemahan:

  • Flashdisk standar tidak memiliki chip cryptographic secure element (seperti YubiKey).
  • Mitigasi: File kunci diikat HMAC-SHA256 & token terenkripsi AES-256-GCM.
